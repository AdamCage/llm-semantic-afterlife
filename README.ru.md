## Вопрос

Дадим языковой модели скользящее окно контекста размером `W` токенов и позволим
генерировать бесконечно. Её состояние — последние `W` токенов; на каждом шаге
входят новые токены, а самые старые выпадают. Примерно через `W` сгенерированных
токенов **исходный промпт физически покидает вход модели**.

```
t = 0     [SEED···························]
t = k     [SEED··············][NEW][NEW]
t > W     [NEW][NEW][NEW][NEW][NEW][NEW][NEW]      ← seed'а больше нет
```

Что происходит с семантическим состоянием генеративной системы после того, как
вся информация о её начальном условии вытеснена из единственной доступной ей
памяти?

Формально, где `V` — словарь, `θ` — фиксированные параметры, а `Tail_W`
оставляет последние `W` токенов:

$$X_t \in V^W, \qquad Y_t \sim P_\theta(\cdot \mid X_t), \qquad X_{t+1} = \mathrm{Tail}_W(X_t \oplus Y_t)$$

Это стохастическая динамическая система с конечной памятью. Репозиторий измеряет
её долговременное поведение.

## Что именно измеряется — и почему это не «посмотрим, куда ползут эмбеддинги»

| Величина | На какой вопрос отвечает |
| --- | --- |
| **Семантическое полувыведение** `T_½` | Сколько сгенерированных токенов проходит, прежде чем исчезает половина измеримой информации о seed'е? Верно ли `T_½ > W`, то есть поддерживает ли модель память через собственный вывод быстрее, чем окно её вытесняет? |
| **Скейлинг MSD** `MSD(τ) ∝ τ^α` | Свободная диффузия (`α ≈ 1`), удержание (`α < 1`, плато) или направленный дрейф (`α > 1`)? |
| **Метастабильные макросостояния** | Существует ли *конечный* набор семантических состояний — подтверждённый implied timescales и тестом Чепмена–Колмогорова, а не подсчитанный по картинке UMAP? |
| **Вероятностные токи** `J_ij` | Необратимы ли переходы во времени: `A → B` намного вероятнее, чем `B → A`? Есть ли реальная неравновесная семантическая циркуляция? |
| **Фазовое поведение `temperature × W`** | Есть ли граница между семантическим удержанием и семантической диффузией? |
| **Области притяжения** | Куда приходят разные seed'ы, и различается ли карта между семействами моделей? |

Центральная предрегистрированная гипотеза:

> После полного вытеснения начального контекста свободно генерирующая LLM не
> совершает неограниченный случайный дрейф по семантическому пространству. Она
> занимает и переключается между **конечным набором модель-специфичных
> метастабильных семантических состояний.**

## Как устроен эксперимент

**Протокол P1 (повторный промптинг).** На каждом шаге отправляются последние `W`
токенов как новый промпт и получаются `B` новых токенов; окно сдвигается на
`S = B`. Это точно реализует рекуррентное соотношение через любой хостируемый
API. Это **не** то же самое, что настоящее скользящее внимание с вытеснением
KV-кэша — позиции перезапускаются на каждом шаге — и это ограничение указано в
разделе о методе, а не спрятано
([ADR-0001](docs/decisions/ADR-0001-reprompt-window-protocol.md)).

**`W` задаём мы, а не модель.** Именно это превращает «сравним пять моделей» в
«зафиксируем `θ` и будем менять память».

**Закон стоимости, определяющий всё остальное.** Поскольку всё окно
пересылается заново каждые `S` токенов:

```
input_tokens ≈ T · W / S            output_tokens ≈ T
```

При `W = 32k`, `S = 1024`, `T = 512k` это 16.4M входных токенов на 512k
выходных — усиление в 32 раза. Если уменьшить `W` и `T` вдвое одновременно,
число оборотов окна сохранится при четверти стоимости — поэтому пилот идёт на
`W = 8k` ([ADR-0004](docs/decisions/ADR-0004-pilot-window-and-cost-law.md)).

**Два пространства представлений, различных по типу.** Qwen3-Embedding-8B
(каузальный декодер) и BGE-M3 (двунаправленный энкодер). Согласие между ними —
свидетельство о генераторе; согласие двух декодерных эмбеддеров было бы
свидетельством только о декодерах.

**Две независимые ветки анализа.**

```
                    эмбеддинги чанков (1024 токена генератора, без перекрытия)
                                    │
              ┌─────────────────────┴─────────────────────┐
              ↓                                           ↓
      ГЕОМЕТРИЯ (без времени)                   ДИНАМИКА (по времени)
      PCA → mutual-kNN → Leiden                 PCA → VAMP → k-means
                                                → необратимая MSM → PCCA+
              └─────────────────────┬─────────────────────┘
                                    ↓
                       согласие (ARI / NMI) по обеим
                       веткам и обоим пространствам
```

VAMP, а не tICA, потому что tICA предполагает обратимую динамику с detailed
balance, а у авторегрессионной генерации есть стрела времени
([ADR-0002](docs/decisions/ADR-0002-vamp-over-tica.md)).

## Пять непреложных правил

Они и делают результат публикуемым; вся оснастка существует, чтобы их соблюдать.

1. **Нет числа без `run_id`.** Каждый график и каждое утверждение отслеживаются
   до `runs/<run_id>/` с полным манифестом.
2. **Воспроизводимость по построению.** run = `configs/**` + git SHA + seed.
   Никаких результатов, живущих только в ноутбуке, никаких правок вывода руками.
3. **Логировать сверх разумного.** Сырые тела запросов и ответов, учёт токенов,
   идентичность провайдера и квантизация, ретраи, проверки round-trip
   токенизатора — append-only JSONL.
4. **Самодостаточные артефакты.** С каждым графиком идут исходные tidy-данные
   (`.data.parquet`), метаданные (`.meta.json`) и подпись, говорящая, что он
   показывает *и чего он не показывает*.
5. **Статистика — в полном пространстве.** UMAP/t-SNE только как иллюстрации, с
   явной пометкой. Никогда — число кластеров по 2-D проекции.

Детерминизм LLM API нигде не предполагается. Он измеряется
(`afterlife audit determinism`) и сообщается как частота.

## Быстрый старт

```bash
git clone https://github.com/AdamCage/llm-semantic-afterlife
cd llm-semantic-afterlife

uv venv --python 3.11
uv pip install -e ".[dev]"                 # ядро + инструменты
uv pip install -e ".[dev,dynamics]"        # + VAMP/MSM/Leiden, нужно с Этапа 3

cp .env.example .env                       # затем впишите ROUTERAI_API_KEY
afterlife doctor                           # проверка окружения, бесплатно
```

Сначала прогоните весь пайплайн офлайн — без ключа, без затрат, и это отловит
большую часть ошибок. Офлайн-генератор — скрытая марковская цепь по пяти темам с
намеренно необратимой матрицей переходов, поэтому у анализа есть известная
истина для сверки:

```powershell
$env:AFTERLIFE_EXECUTION_MODE="mock"
afterlife plan     --config configs/stages/stage0_smoke.yaml
afterlife generate --config configs/stages/stage0_smoke.yaml
afterlife embed    --config configs/stages/stage0_smoke.yaml --run <run_id>
afterlife analyze geometry --run <embed_run_id>
```

Затем живой путь:

```powershell
$env:AFTERLIFE_EXECUTION_MODE="live"
afterlife audit providers        # доступность, квантизация, цены — дёшево
afterlife audit tokenizers       # целостность round-trip — бесплатно
afterlife audit continuation     # какие механизмы продолжения работают
afterlife audit determinism      # измеренная воспроизводимость по seed
afterlife audit embeddings       # размерность, нормировка, стоимость
afterlife estimate --config configs/stages/stage1_pilot.yaml
```

Любая команда, тратящая деньги, печатает прогноз и остаток бюджета и отказывается
превысить `AFTERLIFE_BUDGET_USD_PER_RUN` / `_TOTAL`.

## Этапы

Работа идёт строго по этапам. У каждого есть план, написанный *до* выполнения, с
предрегистрированными предсказаниями, и отчёт после — с явным вердиктом
`PASS`/`FAIL`/`PARTIAL` по каждому критерию выхода. Этап, опровергнувший
собственную гипотезу и честно сообщивший об этом, — успешный этап.

| Этап | Вопрос | Статус |
| --- | --- | --- |
| **S0** | Можно ли это воспроизводимо запустить, за какие деньги, и что провайдеры делают на самом деле? | в работе |
| S1 | Существует ли эффект на ~32 оборотах окна? | план |
| S2 | Семантическое полувыведение и скейлинг диффузии | план |
| S3 | Метастабильность, марковские модели состояний, робастность представлений | план |
| S4 | Фазовый портрет `temperature × W` | план |
| S5 | Области притяжения; чувствительность к начальным условиям | план |
| S6 | Робастность, аблации, репликация на другом провайдере | план |
| S7 | Рукопись | план |

## Новизна, сформулированная честно

Мы **не** первые применяем язык аттракторов к LLM и **не** первые отслеживаем
эмбеддинги по ходу генерации. Существуют смежные работы о последовательном
перефразировании как динамической системе, о LLM как марковских цепях и об
аттракторах в многоходовых диалогах; они каталогизированы со статусом
верификации в
[`docs/literature/related-work.md`](docs/literature/related-work.md), и ничто не
попадает в рукопись, пока не верифицировано.

Наш вклад — конкретный режим:

> неограниченная свободная авторегрессионная генерация при **навязанном** конечном
> скользящем окне контекста, с характеризацией семантической динамики того
> периода, который начинается после полного вытеснения начального условия —
> затухание памяти, скейлинг диффузии, метастабильность и необратимость времени
> как функции размера окна, температуры и модели.
